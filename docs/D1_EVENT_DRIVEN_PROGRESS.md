## Task 1 — the forecast note schema and the freshness functions

**Scope.** `packages/schemas/src/forecast-note.ts` adds the forecast note, `blink.forecast-note/0.1`, as a strict zod schema of at most 65,536 bytes, with four pure functions:
- `parseForecastNote` refuses a BOM, invalid UTF-8, JSON that is not an object, more than 64 KiB, an unknown key, a missing or malformed salt, a non-canonical `marketId`, a bad URL, more than 20 evidence items, and the time and kind contradictions of plan section 2.6. It never serialises a note again.
- `noteBelongsTo` compares the five fields that identify the signed answer.
- `summarizeWindow` counts analysed, carried, no-note and unfetched answers, and merges `CHANGED` items by URL with one witness per answer.
- `computeFreshness` returns CURRENT, AGING (1 or 2 windows behind), STALE (3 or more) or NONE, and takes `evidenceChangedAt` from analysis notes only.

`@blink/schemas` exports the module, and `@blink/client` re-exports it for the agents and the website. The signed `Forecast` type and its domain are unchanged. A new test pins the type string and the digest of one fixed message.

**Rulings during the task.** Plan section 2.6 notes them.
- An evidence item's `fingerprint` may be null only on an `UNREACHABLE` item, for a source that has never been fetched successfully.
- A `carry_forward` note must name its prior answer; `prior: null` is refused.
- The note limits are exported for the note builder: `FORECAST_NOTE_MAX_EVIDENCE`, `FORECAST_NOTE_MAX_URL_CHARS`, `FORECAST_NOTE_MAX_ITEM_NOTE_CHARS` and `FORECAST_NOTE_MAX_SUMMARY_CHARS`.
- A URL must start with a literal `https://` followed by a host character, and may not contain a backslash, a space or a control character. Character limits count code points.
- A refusal reason is capped at 200 characters per part, because the name of an unknown key comes from the sender.

## Task 2 — the source watcher in the reference agents

**Scope.** The reference agents can check whether the pages a market names have changed, with no model call. Nothing in the reference process touches the network.
- `examples/agents/src/lib/fetcher.ts` adds the fetchers and the rules they share:
  - `httpsFetcher` reads a URL over https and nothing else. It judges the URL before any lookup, judges every address the name resolves to before any connection, connects to the judged address, checks that the socket ended there, and judges every redirect again (at most 3). One 10 s deadline covers the whole read, and the decoded body is capped at 4 MiB. It never throws once built; a failure is `{ status: "error", code }`.
  - `fixtureFetcher` serves the world file's source files with a media type from the file extension, and answers `NOT_IN_WORLD` for any other URL.
  - The address rules (`isPublicAddress`, the local-subnet check and `extraBlockedRanges`) live in the file, so an outside developer who copies the example gets its own copy. A test compares them with the platform's.
  - The shared URL and media-type rules: `isCanonicalHttpsUrl`, `jsonBytes`, `isMediaType`, `mediaTypeOf`, `isEtag` and `isLastModified`.
- `examples/agents/src/lib/watch.ts` adds the cheap check:
  - `normalizeForFingerprint` and `fingerprint` turn a body into text that ignores noise, then into a keccak256 hash;
  - `watchableUrl` builds the form of a URL that the watcher accepts, saves and puts into a note;
  - `checkSources` reads every URL once, at most five at a time, and returns the items (`NEW`, `CHANGED`, `UNCHANGED`, `UNREACHABLE`) and the `next` sources table. It does not change the record;
  - `decideUpdate` turns the items into `analyse` (`cold_start`, `change` or `heartbeat`) or `carry_forward`.
- `examples/agents/src/lib/state.ts` adds the `watch` part of the agent state (`WatchRecord`, by market id). `loadState` accepts an older file without it, and refuses a malformed record, a source key that is not a canonical https URL, a validator or final URL or media type that is not in the stored shape, and a probability outside 1 to 9999, all as `STATE_CORRUPT`.
- `AgentContext` has a `fetcher`, and `createContext` takes it as a required option with no default. `main.ts` passes `fixtureFetcher(world)`. The test files that build a context pass the fixture fetcher or a stub.
- World-file source keys must be canonical https URLs, and the error names the canonical form.
- The platform's `isPublicAddress` (`packages/domain/src/network-policy.ts`) now admits only global unicast IPv6 (`2000::/3`), with the registry's globally reachable exceptions inside `2001::/23`. It no longer judges the rest by a list of refused ranges.

**Rulings during the task.** Plan section 2.2 notes the main ones. Each is a departure from the plan as first written.
- The default resolver is c-ares (`dns.Resolver`), not `dns.lookup`: it can be cancelled, it cannot exhaust the thread pool, and it reads no `/etc/hosts` and applies no search domains.
- A and AAAA are queried together. A failure of one does not fail the lookup, and the lookup stops waiting 300 ms after the first non-empty answer (RFC 8305's resolution delay).
- The request asks for `identity`. A gzip or deflate body is still decoded, and both the wire size and the decoded size are capped. `br` is refused (`UNSUPPORTED_ENCODING`).
- Validators (`ETag`, `Last-Modified`) go only on the request for the final URL they were saved for, never on another hop. A 304 counts only when a conditional header was sent.
- An empty body is `UNREACHABLE` (`EMPTY_BODY`).
- JSON nested deeper than 256 levels, or with more than 100,000 structural tokens, is compared as whitespace-collapsed text. Numbers are kept as written.
- A text body is decoded with its declared charset (UTF-8 when none). An unknown label or bytes that do not decode fall back to windows-1252. Only a type that is not text is hashed as `raw:` bytes.
- The local-subnet refusal: an address inside a subnet of one of the machine's interfaces is refused, as is one in `extraBlockedRanges`. It covers the IPv4-mapped, NAT64 and IPv4-compatible forms of an IPv6 address. A range written as `::ffff:a.b.c.d/n` is converted to the IPv4 range it maps to.
- No `User-Agent` and no cookie is sent.
- Any of five proxy variables (`HTTPS_PROXY`, `https_proxy`, `HTTP_PROXY`, `http_proxy`, `NODE_USE_ENV_PROXY`) makes `httpsFetcher` throw `PROXY_CONFIGURED` at construction, unless `direct: true` is passed.
- A source URL, a stored final URL and a world-file key are canonical (`new URL(u).href`) and take at most 2,048 bytes once JSON-encoded (`SOURCE_URL_NOT_CANONICAL`).
- Only values that `loadState` accepts are stored: validators, final URLs and media types. A validator or final URL that fails the shape is not stored, and an invalid media type becomes `application/octet-stream`.
- `checkSources` throws a `RangeError` on input the caller should have filtered: a `now` that is not whole seconds, more than 20 URLs once repeats are removed, a non-https or non-canonical URL, or one over 2,048 bytes. Build the list with `watchableUrl`.
- `next` holds only the URLs of this check. A URL whose first check failed gets no entry, so its first success is `NEW`. `SourceCheck.fingerprint` is null only for that case.
- `decideUpdate` throws on a heartbeat that is not finite and positive, and counts a prior analysis dated after `now` as due.
- The check yields to the event loop between sources, so timers and socket callbacks are not held up. It does not run another role's tick: `runAgent` runs one tick at a time, so the other roles wait for the whole check.
- The linkability limits are stated in the `fetcher.ts` header and in plan section 2.9: a per-request token reaches the fingerprint and the public snapshot, and validators let a server recognise the agent across windows and IP changes. Unlinkability needs a tunnel.

## Task 3 — the event-driven forecaster

**Scope.** The reference forecaster analyses a market only when something changed, and otherwise signs its earlier probability again. Each answer signs the keccak256 of a forecast note that was uploaded before the submit.
- `examples/agents/src/roles/forecaster.ts` exports `createForecaster({ now })`, whose tick follows plan section 2.4 for each open window. The default `forecaster` is `createForecaster()`.
  - It checks the sources once per window, decides with `decideUpdate`, calls the model's `revise` on `analyse`, and takes `prior.probabilityBps` on `carry_forward`.
  - It builds the note, saves the intent (the exact note bytes, with the snapshot files and the fingerprints to commit), uploads the note, signs `Forecast` with `contentHash = keccak256(note)` and submits.
  - After a successful submit it commits the fingerprints, `prior` and the window id in one state save.
  - After the platform lists the window as `CLOSED`, it uploads the snapshots that the note names, and settles an intent whose window closed before it could be resubmitted.
- `examples/agents/src/lib/note.ts` builds the note bytes (a fresh 32-byte salt, the schema's limits, and the dropping order that keeps a note within 64 KiB without ever dropping a `CHANGED` item) and decides which changed sources may be archived (the five media types the content route accepts, at most 1 MiB).
- `examples/agents/src/lib/model.ts`: `Model` gains the optional `watchList(m)` (default: the spec's `sources`) and `revise(m, { prior, changes })` (default: `probabilityBps(m)` with an empty summary). The fixture model implements both from the agent's own beliefs.
- `examples/agents/src/lib/env.ts` reads `BLINK_FORECAST_HEARTBEAT_HOURS` (default 336, that is 14 days); the context carries `heartbeatSeconds` and `stateDir`. An empty or blank value counts as unset (the other variables are required, and an empty one counts as missing), and a value that is not a plain positive decimal is `INVALID_ENV:BLINK_FORECAST_HEARTBEAT_HOURS`.
- `examples/agents/src/main.ts` exports `agentParts(env, world)`, which returns `{ model, fetcher, heartbeatSeconds }` and always builds `fixtureFetcher(world)`. The process never fetches from the network.
- `examples/agents/src/lib/state.ts`: an intent also holds `next` (the fingerprints it was based on) and `sent` (saved before the first submit), both validated by `loadState`. `writeFileDurably` flushes a file before the state that names it.
- `apps/web/content/docs/forecaster.md`: the Steps name `uploadContent`, `getForecastWindow` and `listForecasts`, name the `content:write` scope next to `forecast:write`, and say that `contentHash` is now the hash of a note. The "Reasoning is optional" bullet no longer says that the reference forecaster publishes no reasoning document. The page keeps its six H2 sections. The full rewrite is Task 6.
- `@blink/client` also exports `isHttpsUrl` and the `ForecastNoteItem` schema; `@blink/schemas` exports `isHttpsUrl`.

**Rulings during the task.** Each is a departure from the plan as first written, or a bound the plan left open. Plan section 2.4 notes the main ones.
- The watch list is built in one place. Each URL goes through `watchableUrl`; repeats are removed after mapping; the list is capped at 20, the spec's `sources` first. The log lines are `watch_url_too_long` (an https URL over 2,048 bytes as JSON), `watch_url_invalid` (anything else that is refused) and `watch_list_truncated`. A `RangeError` from `checkSources` is a bug, not a market condition.
- Work per tick is bounded, because `runAgent` runs one tick at a time and a check of 20 silent URLs lasts about 40 s:
  - `MAX_MARKETS_WORKED_PER_TICK = 2`. A fresh check, a model call or the resubmit of a saved intent each count once per market. A market that is out of budget is where the next tick starts, so every market gets its turn, also after a 429 or an `INDEX_STALE`.
  - Snapshot uploads: at most 20 objects (`SNAPSHOT_UPLOADS_PER_TICK`) or 8 MiB (`SNAPSHOT_BYTES_PER_TICK`) a tick, one upload per hash even when several markets share it, and the next tick starts with the market where the allowance ran out.
  - `PRUNES_PER_TICK = 2`. A market whose windows cannot be read goes to the back of the order, so failing markets cannot starve the rest.
- An idle market (everything open is answered, given up or without a view) is listed at most every `WINDOW_RECHECK_SECONDS` (30 s) and at least 5 s apart. A platform time (the next `openAt`, or the deadline) is trusted only within that horizon, and an empty window list counts as 30 s, so a skewed local clock or a short window is never missed. A clock that went back voids the skip.
- The windows read does not stop at a page that ends with an `OPEN` window while a `nextCursor` exists: it stops at a page with an `UPCOMING` window, at the last page, or after two pages. The saved cursor moves only past pages that are wholly `CLOSED`.
- A 4xx other than 408 and 429 from the note upload or the submit is final for the window: `forecast_refused` with the code, the window is marked, the intent and its snapshots are dropped in one save. An intent whose submit may have reached the platform (`sent`) is kept instead and settled after the window closes, so a lost response does not lose the record of the answer.
- A resumed submit commits the intent's saved fingerprints in the same save as `prior`, so the next window sees a carry-forward or a heartbeat, not a second analysis of the same change. The settle-after-close path stays uncommitted, as the plan says.
- Errors are caught per market and logged with a stable code (`forecaster_market_error`). A code is an API error's code, one of an allowlist of this agent's own codes, or the error's name; a message is never logged. A 429 or a 503 `INDEX_STALE` is not a market's failure and is left to the loop's wait.
- A URL that the note schema refuses (a backslash survives in the query or the fragment of a canonical URL) is never watched: `isCanonicalHttpsUrl` also requires the schema's exported `isHttpsUrl`, and so do `watchableUrl`, `loadState` and the world-file keys. `buildNote` drops a non-`CHANGED` item that fails `ForecastNoteItem` and throws for a `CHANGED` one.
- The subject of a saved note is checked with `noteBelongsTo` before it is signed; a mismatch drops the intent with `INTENT_SUBJECT_MISMATCH`.
- State is written durably: the snapshot file and the state's temporary file are flushed before the rename or the reference. Housekeeping removes the files in `snapshots/` that no record names, and never one that a record names.
- The in-memory state (memos, windows seen, window statuses, retry times, idle times, where the next tick starts) is kept per context in a `WeakMap`, so two contexts in one process never share it.
- A 404 from `getForecastWindow` for the window of an intent or a snapshot is final: the intent or snapshot is dropped. A lookup that keeps failing for 24 hours (`SNAPSHOT_GIVE_UP_SECONDS`) gives up the same way.
- A 400 `INVALID_CURSOR` for the saved `windowsCursor` deletes it and reads from the first page.
- The retry spacing reads a fresh clock at the spacing test and again when an attempt fails, so a slow check does not let attempts 2 and 3 run seconds apart. A cached open window, a retry time and a spacing that lie further ahead than their interval mean that the clock went back, and count as due.
- Pruning a market that left `OPEN` (nothing pending for it) also removes the ids of its windows from the answered list `forecaster.submitted`, so the state does not grow with every market ever seen.
- The fixture model's `watchList` returns nothing for a market the agent has no belief about, so a page it has no use for is not fetched.
- `analysedAt` is the note's `checkedAt`, the time of the check that the analysis was based on.
- The content route accepts five media types (`application/json`, `text/plain`, `text/csv`, `text/html`, `application/pdf`) and at most 1 MiB (`packages/schemas/src/http.ts`); any other type is a `415`. A pending snapshot's media type is the one the fetcher reported, which already passes `isMediaType`.

**Limits.**
- One agent per state directory is the supported setup, and the directory itself is not flushed.
- Idle state is in memory, so a restart lists every market once.
- A long `PRE_CLOSE` window that sorts after a `DAILY` window can be picked up late, never missed.
- One intent is saved per market, so a kept sent intent can block an overlapping window of the same market until it is settled.
- A forward jump of the local clock can make a snapshot give up before the 24 hours have passed.
- A 401 or 403 loses that window, as any other final refusal does: the model has already been paid for it, and the next window runs again.

## Task 4 — reading freshness from the public routes

**Scope.** `packages/client/src/freshness.ts` adds `getMarketFreshness`, a function that takes a client and a market id and returns the market's freshness and its windows, through the public routes only.
- It reads the deployment once, for `generation.markets`.
- It pages the windows, stopping at the first one that is not CLOSED, and pages the consensus. It keeps the latest 30 closed windows.
- For each window that has answers, it lists them and ignores the withdrawn ones.
- It fetches at most 20 notes per window, 8 at a time. `NO_CONTENT_HASH` is never fetched, and the answers past the limit are `unfetched`.
- A note counts only if it parses and `noteBelongsTo` accepts it. Every other answer counts as an answer without a note.
- It reduces the windows with `summarizeWindow` and `computeFreshness`.

`@blink/client` re-exports the reader and its types. `apps/web/content/docs/client.md` gets a subsection and an exports row, and the method count stays at 36, because the reader is not a method of the client. `apps/web/content/docs/forecaster.md` gets a bullet under Duties, and its six H2 sections are unchanged.

**Rulings during the task.** Each is a departure from the plan as first written. Plan section 2.5 notes them.
1. The reader calls `getDeployment()` once, because `noteBelongsTo` needs the generation's `BlinkMarkets`.
2. The parameter is a structural `FreshnessClient` type, to avoid an import cycle. A compile-time test pins that the real `createBlinkClient(...)` fits it.
3. Windows that share a `scheduledAt` (a daily and a pre-close window on the same deadline) are one window, with the earliest `openAt`, so `windowsBehind` does not count a deadline twice.
4. Only a missing note (a 404 from the store) or a hash mismatch counts as an answer without a note. Any other content-route failure (a 429, a 5xx, a network error) throws, as the window, consensus and answer routes do. A retry with the same `cache` fetches only what is missing.
5. Bytes are used only if they hash to the requested hash, whether they were fetched or came from the cache.
6. Invalid options throw a `RangeError` (`INVALID_WINDOWS`, `INVALID_NOTES_PER_WINDOW`, `INVALID_AS_OF`), and a cursor that does not move throws `CURSOR_NOT_ADVANCING`.
7. "Closed" is the server's `status === "CLOSED"`. `asOf` only sets the time the view is for.

## Task 5 — the website shows freshness and what changed

**Scope.** The market page shows how fresh the consensus is and which evidence changed. It runs on the labelled sample markets, through the same `computeFreshness` that a live reader uses.
- `FreshnessLine` (`apps/web/components/markets/FreshnessLine.tsx`) is a server component in the consensus card. For an open market it shows the level, the latest window, the windows behind, "N of M answers reported a new analysis" and "K sources changed (reported)". The analysed count and the changed sources are marked as reported. A market that is not open reads "Forecasting ended at close; last window <date>" and shows no level.
- `EvidenceChanges` (`apps/web/components/markets/EvidenceChanges.tsx`) is a server component in a new "What changed" section between the chart and "How it resolves".
  - It lists the reported changes, newest first, each with the source host, "changed between X and Y (UTC)" (since and observed), one summary, the move of each forecaster, and the snapshot hash as text. Nothing links to a snapshot, because the static site cannot check one.
  - A source checked for the first time is listed apart, never as a change. A change without a snapshot reads "Snapshot not available".
  - The section carries the line "Reported by the forecasters; an archived snapshot can be checked against its hash."
- `ForecastChart` draws a marker on the baseline at each window with a changed source, and a hollow point at each window where every answer was carried forward. The legend, the tooltip ("Sources changed: N (reported)", "New analysis A, carried C") and the table (the columns "New analysis / carried" and "Sources changed") say the same. The chart still receives plain numbers and imports neither `zod` nor `@blink/schemas`.
- `apps/web/content/sample-freshness.ts` exports `sampleWindowSummaries(m)`, which turns the sample windows into the reader's window summaries, and `sampleFreshness(m)`, which runs `computeFreshness` over them (null for a market that is not open). Only the market page and the tests import it.
- The sample-market fixtures (`apps/web/content/sample-markets.ts`): each window gains `analysed`, `carried`, `changes` and `firstChecked`, and the sample values were reworked to keep the rulings below.
- "Sample data" is shown next to the freshness line and in the "What changed" lede, and each sample snapshot hash is marked "(sample)".
