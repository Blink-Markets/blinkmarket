_Status: completed — implemented on 2026-10-09 (0093a3c, 2466208; delivery record docs/M4_WEB_SHOWCASE_DELIVERY.md, "Docs system" section); the page set was later reframed around market roles. Current design: docs/superpowers/specs/2026-10-23-autonomous-market-design.md._

> Date: 2026-10-09
> Scope: replace the current `/docs` and `/docs/api` of `apps/web` with a technical documentation system similar to the Claude Code docs.
> Status: design approved in conversation (two tracks, Markdown + marked, no Open in Claude / ChatGPT); visual details are iterated with screenshots during implementation, with no separate mockup page.

## 1. Goals

The technical documentation must be clear, browsable by topic, and directly usable by an agent.

- **Human version** (`/docs`): multiple pages, grouped by topic, explained in layers; every page can copy its Markdown, view its Markdown and copy a prompt for an agent; commands and agent guidance can be copied in one click.
- **Agent version** (`/docs/agents`): a step-by-step guide that tells the agent directly how to install and what to do, with the necessary principles, rules and technical details; plain Markdown (`/docs/agents.md`) and an `/llms.txt` index are also provided.

Success criteria:

1. Every human-version page has a matching `/docs/<slug>.md` whose content is identical to the source file word for word; `/docs/agents.md`, `/docs/api.md` and `/llms.txt` exist and are generated statically.
2. "Copy page" copies the whole page's Markdown; "View as Markdown" opens the `.md`; "Copy prompt for agent" copies a prompt containing the current URL; code blocks and Agent prompt blocks can be copied.
3. Every internal `/docs/...` link inside any Markdown points to an existing page (guaranteed by a test).
4. The documentation states only facts that can be verified in the repo; unimplemented endpoints are always marked Planned; no domain, package or deployment is invented.
5. No horizontal overflow at 375px; the left navigation collapses on phones; `pnpm check` and `pnpm build` pass.

### 2.2 Agent version

`/docs/agents` (HTML) and `/docs/agents.md` (the same content as plain Markdown), with a fixed structure:

1. Purpose and hard constraints: testnet, assets have no value, not deployed, which features are not live, and prohibitions (do not create wallets, do not sign or broadcast transactions, an API key does not mean it can withdraw funds on someone's behalf).
2. Install and run locally: commands to copy as written (Node 22.23.1, pnpm 11.20.0, clone, install, check, dev).
3. Verify: `curl http://127.0.0.1:3001/v1/config` and similar, with the expected output.
4. Core model: concise definitions of Market, MarketSpec, forecast window, quote, complete set, INVALID and finality.
5. Workflows: authenticate → read markets/specs → submit forecasts (with Idempotency-Key). Each step lists the endpoint, the required fields and the status (which API mode enables it / Planned).
6. Rules and invariants: the rules that must be followed.
7. Endpoint status table.
8. Troubleshooting: the meaning of 400/501/503.

### 2.3 Machine-readable endpoints

- `/docs.md`, `/docs/<slug>.md`: the source text of the human-version pages.
- `/docs/agents.md`: the source text of the agent guide.
- `/docs/api.md`: a Markdown table generated from the openapi-index.
- `/llms.txt`: an index following the llms.txt convention (a title, a one-sentence summary, each `.md` link with a one-sentence description), with links given as relative paths or paths without a domain at build time, and no invented domain.

## 3. Layout and interaction

- The docs area has its own layout: the top reuses the site header and testnet notice; below it is a row that switches between "For humans | For agents".
- Three columns (≥1100px): grouped navigation on the left (sticky), the article in the middle (about 72ch), and "On this page" on the right (h2/h3). 768-1099px: the right column is hidden. <768px: the left navigation collapses into a "Menu" disclosure (`<details>`), which also works without JS.
- Page header: group name, title, description, and a **Copy page** split button (the main button copies Markdown; the menu has View as Markdown and Copy prompt for agent).
- Code blocks: a language label + a copy button; no syntax colouring.
- Callout boxes (written in Markdown with GitHub alert syntax, so the source stays readable): `> [!NOTE]`, `> [!PLANNED]` (not yet live).
- Agent prompt block: written in Markdown with a ```` ```prompt ```` fence and rendered as a prominent block with a "Copy prompt" button; in the source it is still an ordinary code block.
- Copy prompt for agent template: `Read {origin}/docs/agents.md first and follow its rules. Then use {origin}/docs/<slug>.md to <frontmatter.agentTask>. Blink runs on the Base Sepolia testnet with test assets only; do not create wallets, sign or broadcast transactions unless I explicitly ask.` `{origin}` is taken from `location.origin` at click time.
- Visuals: reuse the site tokens (paper, cobalt, ink, Geist / Geist Mono); the docs area has no large illustrations and does not enable the blink-open reveal animation; terracotta is used only for the Planned marker and for the navigation indicator of the current page.
- Copy feedback: the button text briefly changes to "Copied"; if the clipboard fails, it falls back to selecting the text.
- Light/dark toggle (added on 2026-10-09 from mockup feedback): it affects only the docs area (`html:has(.docs-root)`); the showcase pages stay light (illustrations use fixed ink colours). It follows `prefers-color-scheme` by default; the toggle button (at the right of the audience row) stores the choice in `localStorage` (key `blink-theme`) and sets `<html data-theme>`; the root layout applies it with an inline script before first paint to avoid flicker. Dark tokens: paper `#141518`, paper-2 `#1c1e22`, ink `#ecebe5`, cobalt `#8ea6f2`, terracotta `#e08a66`, rule `#ecebe529`; the header eye uses `currentColor` to keep contrast in dark mode.

## 4. Technical design

- Content: `apps/web/content/docs/*.md` (human version) and `apps/web/content/docs/agents.md`. The frontmatter (a `---` block, single-line `key: value`) fields are `title`, `description`, `group`, `order`, `agentTask`. A minimal frontmatter parser is written in-house, with no package added.
- Rendering: add one third-party dependency, **marked 18.0.13** (released 2026-09-12, more than 2 weeks old). A custom renderer handles heading ids (slugified), code → a structure wrapping a copy button, the `prompt` fence → an Agent prompt block, and GitHub alerts → callout boxes. The output HTML is inserted with `dangerouslySetInnerHTML` (the content is trusted files inside the repo).
- Module boundaries:
  - `apps/web/lib/docs/frontmatter.ts` (pure function)
  - `apps/web/lib/docs/registry.ts` (reads files, sorting, navigation tree, slug ↔ file; server-only)
  - `apps/web/lib/docs/render.ts` (marked configuration, heading collection for the table of contents)
  - `apps/web/lib/docs/llms.ts` (llms.txt generation)
  - `apps/web/components/docs/*`: `DocsShell`, `Sidebar`, `Toc`, `CopyPageMenu` (client), `CodeCopy` (client; binds behavior to the rendered buttons)
- Routes: `app/docs/[[...slug]]/page.tsx` (`generateStaticParams`); the Markdown source is served by a route handler (`app/docs-md/[...slug]/route.ts`, `dynamic = "force-static"`), with `next.config.ts` rewrites mapping `/docs.md` and `/docs/:path.md` to it; the implementation must first read the rewrites documentation in `node_modules/next/dist/docs` and test with `next start`. `app/llms.txt/route.ts` is generated statically. `/docs/api` stays a React page and reuses `openapi-index.ts`.
- Replacement: delete the existing `app/docs/page.tsx`, `app/docs/layout.tsx` and `app/docs/docs.module.css`; `app/docs/api/page.tsx` switches to the new layout.

## 5. Testing

- Unit (`tests/web-docs-*.test.ts`): frontmatter parsing (including an error on a missing field), navigation sorting and grouping, unique heading ids, rendering of the `prompt` fence and alerts, llms.txt listing every `.md`, and complete frontmatter on every page.
- Content integrity: every `/docs/...` link (including `.md`) in any Markdown exists; no `TODO` / `TBD`; `agents.md` contains the eight section headings of §2.2.
- Post-build check: under `next start`, use curl to verify the status, `content-type` (`text/markdown; charset=utf-8`, `text/plain; charset=utf-8`) and word-for-word content of the `.md` endpoints and `/llms.txt`.
- Screenshots: desktop and 375px; use a CDP script to actually click Copy page / Copy prompt and read back the clipboard content (or intercept `navigator.clipboard.writeText`).
