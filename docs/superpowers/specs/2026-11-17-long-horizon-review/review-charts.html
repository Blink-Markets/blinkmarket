審查結論：這套設計還沒有解決原始問題

原始問題是：長期題目要怎麼讓參與者早點進場，而且早期預測準確。獨立審查者坐進每個參與者的位置，用 repo 裡的真實參數試算，結論有四點。

  • 預測者早期進場會賠錢報酬是優勢的平方，質押卻要一比一鎖到結算。
  • 攻擊者有便宜的獲利路徑拉歪基準線再修正、或拉歪後向 maker 買進，都算得出正報酬。
  • 獎金的來源撐不起來創建者最多回收 25 bUSD；出資者付的錢八成進了 treasury。
  • 預測層的差異很薄，整個專案則還有幾處沒找到先例全 agent 市場和密封預測紀錄各自已有人做。開市挑戰、可重算結算、按角色的 credit、鏈上安全上限這四項沒找到相同做法，但各只搜過一次。

預測者實際拿到多少

付款公式是「曝險 ×（自己的分數 − 基準線的分數）」。算出來的期望報酬等於曝險乘上優勢的平方。比基準線準 10 個百分點，只值質押額的 1%。

攻擊者怎麼賺

紀錄裡寫「拉歪基準線再修正，無利可圖」。這只在後面視窗的預算不會變大時成立。預算滾存和任何人可加碼，正好讓它變大。

26 項決策現在的狀態

點任一格看審查者對它的判斷。審查者建議重開 15 項，其中 5 項有具體算例推翻。

經得起檢驗的部分

  • 同一視窗內拆成多個身分不會多賺。審查者做了 20 萬次隨機搜尋，差額最大值是 0。
  • 出資者每個視窗最多付出該視窗的預算。
  • 只看單一視窗、也不交易時，誠實回報是最佳策略。
  • 逾期不揭露罰最大損失時，選擇性揭露得不到好處。
  • 抄共識的 credit 為零。
  • 撤回跨市場共用獎池是對的；用垃圾題抽乾共用池的攻擊擋不住。

和現有平台比

連網調查查了已上線的平台。「所有角色都由 agent 擔任」和「密封、可驗證的預測紀錄」各自都有人做了，但沒有找到把兩者合起來、再依計分付款的平台。

差異化要成立的三個條件

審查者認為下面三件事要同時成立，目前都沒有證據。

  1. 在別處沒有的題目上，共識可量測地勝過單一前沿模型。
  2. 題目覆蓋量比現有平台高一到兩個數量級。
  3. 有人為此付錢。

審查者提的五個方向

都是提議，沒有驗證。最有希望的排前面。

  1. 短期冷門題的機率即服務。企業、DAO 或其他 agent 對自己的營運問題，幾小時內拿到多個有質押 agent 的密封答案。會改動 Q24 和 Q2。
  2. 可計算題目工廠。用模板自動生成大量每週結算的子題，覆蓋別的平台不列的長尾，直接解決回饋延遲。會改動 Q20 和 U13。
  3. 預測 agent 的實測場。把結果發生前就密封、有質押的紀錄當成產品，賣給模型實驗室和 agent 開發者。前提是計分搬到鏈上。會改動 Q3。
  4. 按對共識的邊際貢獻付款。報酬等於「含他的共識得分」減「不含他的」，獎勵獨立資訊。拆分身分是否有利還要另外證明。會改動 Q14。
  5. agent 營運者的避險題目。推理價格、API 可用性、gas 這類別處不列的題目，帶來非資訊性的需求。會改動 Q6。
